# RunOtter 开发包初步审阅

日期：2026-10-25。原开发包代号 Agent Dock；下列问题尚未修改原始规格。

## 初步审阅发现

以下均为对本地文件的静态分析，不是已出现的运行故障；尚未修改原规格。

1. **危险审批规则互相冲突。** SPEC.md:192 允许未注册 WebAuthn 时退回设备令牌与弹窗，SPEC.md:193 又要求无断言不能提交；PROMPTS.md:161、169 同样冲突。M5 前需统一验收口径。建议采用危险操作必须有有效断言的保守规则，未注册时引导先注册。
2. **历史版本缺少完整数据模型。** SPEC.md:295 要求同幂等键更新并保留历史；schema.sql:29 的 artifacts 只存当前 path/version，且 idempotency_key 唯一。仅保留旧文件不足以稳定列出历史元数据与 diff。M2 需设计独立版本记录或明确可检索的版本清单，同时保持列表不重复。
3. **按项目成本缺少明细维度。** SPEC.md:325 要求项目花费 Top 5，但 schema.sql:181 的 cost_daily 只有按天汇总，没有 project。M6 需补 usage 明细或按项目日汇总，以及用量上报入口与幂等约定。
4. **通知六小时去重与永久唯一键需衔接。** SPEC.md:306 使用六小时窗口；schema.sql:137 是全局唯一键。M3 需说明窗口外复用键时如何再次派发并保存审计，不能直接重复 INSERT。
5. **localStorage 范围不一致。** SPEC.md:97 要求保存阅读进度，SPEC.md:333 只禁存令牌；AGENTS.md:39 与 PROMPTS.md:63 的字面约束更广。按需求事实源可仅保存非敏感进度；认证数据仍只走安全 cookie。实现前需在工程约定中写清范围。
6. **数据库数量与邮件描述不符。** 实测 15 张普通表和 1 张 FTS5 虚表，另有 SQLite 自动生成的 FTS 内部表；邮件写的是 13 张表。文件长度与四个独立附件一致，因此不是下载缺失。
7. **设置与已读状态的持久化仍需设计。** 通知项目开关、设备阅读状态、主题等页面需求已列出，当前 schema 未给出相应完整存储结构；按阶段补充，不能把占位交互当作完成。
8. **PDF 预览与 CSP 存在冲突。** SPEC.md:93 选择原生 embed，SPEC.md:340 设置 object-src 'none'，会阻止 embed。M2 需选择符合 CSP 的预览方式或明确调整策略。
